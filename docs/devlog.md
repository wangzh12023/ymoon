# 开发历程与 AI 使用说明

本文记录 ymoon 是怎么做出来的、AI 在其中做了什么、我如何检查它的产出。赛事要求"AI 可以参与开发，但最终成果必须由参赛者理解并负责"，这里把每一个关键决定和验证手段都写清楚。

## 选题过程

1. **调研赛事规则**：官网是 JS 渲染的单页应用，直接抓取 JS bundle 和飞书章程原文，确认评审看重"真实可用、边界清晰、测试可运行、文档完整"，验收要求 CI、完整测试、发布 mooncakes。
2. **调研往届获奖项目**（OSC2026 等）：获奖的全部是可复用基础设施，并且都有"与参考实现对拍"的硬证据（tokenizers 对 39 个模型、raft 逐行移植、toml-test 通过率）。
3. **扫描生态空白**：拉取 mooncakes 全部约 2900 个模块和 GitHub 代码搜索。YAML/TOML/JSON Schema/MCP/压缩/加密/Unicode 都已经有人做到官方测试集；**Yjs 兼容实现为 0**，同时 Yjs 的需求最大（周下载约 1000 万）。
4. **确认技术可行性**：在本机实测 `moon prove` + z3 可用，并且发现切换到机器整数前奏（`MOON_PROVE_PRELUDE_OVERRIDE`）后证明器能检查溢出，这决定了"形式化验证核心"这一卖点。

## AI 的角色

开发使用 Claude（Claude Code）作为编程助手。分工如下：

| 环节 | AI 做了什么 | 我如何验证 |
|---|---|---|
| 移植 YATA / 编解码 | 对照 yjs 源码逐文件翻译为 MoonBit | 差分测试逐字节对比 JS 输出，任何偏差都会定位到具体 step 和具体字节 |
| lib0 编码 | 实现 varint、字符串、writeAny | 用 lib0 生成的参考向量逐字节比对（含 NaN、-0、2^31 边界、孤立代理项） |
| JSON 数字格式 | 实现 JS `Number#toString` | 用 V8 生成 33 个边界值向量（5e-324、1e21、0.1+0.2…） |
| 形式化证明 | 编写契约、循环不变式、引理 | `moon prove` 机器检查；未证明的目标会报出具体公式 |
| 性质测试 | 编写 CRDT 定律 | 反例用 JS yjs 重放，区分"ymoon 的 bug"与"yjs 本身的行为" |

## 测试发现并修复的真实问题

- **search marker 不能省略**：最初以为索引缓存只是性能优化。差分测试显示它决定了 item 在哪里被切分，于是完整移植（包括 Array.reduce 的平局规则）。
- **格式属性按引用比较**：yjs 用 `===` 比较对象值的属性。ymoon 改为保存解析后的值并按物理相等比较，与 JS 对象身份语义一致。
- **`Doc.get` 升级占位类型会重置格式标记**：远端先创建的根类型在本地首次访问时，JS 会新建实例，只拷贝 `_map/_start/_length`。这个细节影响后续 marker 的使用。
- **证明器抓到的溢出**：`clock < start + len` 在 Int32 下可能溢出，改为 `clock - start < len`。
- **性质测试抓到的 bug**：带偏移集成 struct 后缓存的时钟算错，导致后续 struct 永久 pending。已修复并加回归测试。
- **不是 bug 的发现**：并发插入落在代理对中间时，yjs 自身也会在不同 peer 上得到不同结果（U+FFFD，yjs issue #248）。ymoon 与 yjs 行为一致，测试中把它记录为已知行为。

## 关键权衡

- **为什么逐行移植而不是重写**：重写可以更快，但字节兼容要求复现所有实现细节；逐行移植让每个差异都可以追溯到原始代码。
- **为什么 transport 与 room 逻辑分离**：`moonbitlang/async` 在 Windows 上需要 MSVC，而房间逻辑本身是纯函数式的状态机。分离后同一份 MoonBit 代码可以在 native、Node.js、测试桩里复用。
- **性能**：本机 native 后端在 automerge-paper 轨迹上约 2.0 s，V8 上的 yjs 约 1.0 s。分析后确认主要开销在每次事务的固定成本，保持算法与 yjs 相同是字节兼容的前提，因此先保证正确，再优化。
